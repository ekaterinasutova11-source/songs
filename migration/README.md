# Перенос Songs в Selectel

## Архив учеников

В кабинете преподавателя есть вкладки «Ученики» и «Архив». Кнопка «В архив»
открывает подтверждение закрытия доступа без удаления материалов. В архиве
можно открыть репертуар преподавательским доступом и нажать «Восстановить».
Прежняя ученическая ссылка после восстановления снова работает.

SQLite мигрируется автоматически при запуске `songs`: добавляются nullable
`folders.archived_at` и integer `folders.access_version` с default 0. Переносить
или пересоздавать базу для этого не нужно. Перед обновлением снимается резерв.
После появления архивных учеников нельзя откатывать API на версию, которая не
проверяет эти поля: старая версия может снова открыть доступ по ключу.
Восстановление restic snapshot с архивом выполнять с актуальным кодом API.
Проверка целостности и резервирование сохраняют материалы всех неудалённых
пространств, включая архивные.

## Рабочее переключение 20 октября 2026 года

Рабочий сайт по прежнему адресу `https://ekaterinasutova11-source.github.io/songs/`
использует API `https://135.106.183.211/api`. Все прежние hash-ссылки преподавателя
и учеников сохранены. Интерфейс доступен и непосредственно на Selectel.
Старый URL Yandex Cloud Function теперь совместимый шлюз к Selectel, поэтому
уже открытые вкладки также не пишут на Яндекс. Ошибки шлюза возвращаются с 424,
чтобы старые клиенты не включали устаревшую Google-копию при отказе Selectel.
Яндекс остаётся исходной копией, записи приложения идут только в Selectel.

Сервер `songs-app`, Москва / `ru-7a`, IP `135.106.183.211`:
Shared `PRC20.2-2048`, 2 vCPU с гарантированной долей 20%, 2 ГБ RAM,
сетевой SSD Базовый 40 ГБ, один прямой публичный IP, без облачного роутера.
Расчёт панели при заказе — 1 715 рублей в месяц. Дополнительные платные
хранилища, базы и резервирование провайдера не подключались.

Установлены Ubuntu 24.04 LTS, Node.js 24.16.0, SQLite, nginx, Certbot 5.8.0,
restic. API работает от отдельного системного пользователя `songs`, слушает
только `127.0.0.1:3000`, перезапускается через systemd. SSH — только по ключу;
входящий порт 22 ограничен внешним IPv4 владельца в группе безопасности.

HTTPS: `https://135.106.183.211`, публично доверенный сертификат Let's Encrypt
для IP. Продление проверяется дважды в сутки, ошибки повторяются с интервалом
5 минут до четырёх попыток за час. Тестовое продление с deploy-hook прошло.
При замене публичного IP потребуется перевыпуск сертификата и изменение URL.

Развёрнут новый совместимый API (`server.mjs`, `local-store.mjs`) с локальными
файлами и SQLite. База содержит прежние ID и ключи 11 пространств. Исходные
имена файлов сохранены, в том числе имя с двойным пробелом. Файлы представлены
неизменяемыми SHA-256 blobs, удаления логические; прежние версии сохраняются.
Доступ к аудио — по подписанным ссылкам с проверкой срока и отзыва ключа,
поддерживаются GET, HEAD и HTTP Range. Загрузки потоковые, до 256 МиБ.

**`READ_ONLY=false`: загрузки и правки включены.** Перед переключением старый API
временно блокировал изменения. Финальный снимок Яндекса содержит 233 файла,
1 329 741 396 байт и 11 пространств; изменений относительно проверочной копии нет.
Все ID и ключи совпадают. База на сервере побайтно по активным строкам сверена
с финальным импортом. После переключения шлюза каталог и настройки Яндекса
повторно проверены: поздних изменений нет. Google fallback в опубликованном
фронтенде выключен. Прямая личная ссылка: `secrets/Selectel-test-link.txt`.

69 тестов проходят. Через HTTPS проверены все 11 ученических доступов и запрет
чтения чужих папок, метаданные 6 пространств, полное содержимое 74 TXT,
первые диапазоны всех 152 аудиофайлов. На сервере SHA-256 проверен у всех 233
файлов. Корневая страница открывается в браузере без предупреждения сертификата.
В браузере реально проверены воспроизведение минуса Happy, перемотка к середине,
продолжение после неё, шаг назад на 5 с, переключение на оригинал, перемотка

библиотека до и после smoke-тестов совпала. Физические телефоны отдельно не
проверялись.
После публикации проверены и прежние GitHub Pages ссылки: ученическая,

201,39 с без ошибок audio. Прежняя ссылка преподавателя открыла 11 карточек.
Опубликованная цепочка JS использует `selectel1`, API и media origin — Selectel.
Итоговый отчёт: `outputs/selectel-cutover-verification.json`.
Отчёт без ключей: `outputs/selectel-live-verification.json`.

## Резервирование и обслуживание

- `songs-backup.timer`: ежедневно с 05:30 до 05:40 по Москве, с догоняющим
  запуском после простоя. SQLite копируется через `.backup`; затем restic
  шифрует согласованную базу, blobs, конфигурацию и код. Хранилище сервера:
  `/var/backups/songs-restic`. Политика: 7 дневных, 4 недельных, 2 месячных копии.
  После копии выполняются очистка неиспользуемых блоков и проверка репозитория.
- Задача Windows `Songs Selectel Backup`: ежедневно в 06:00 по местному времени
  и при входе владельца в Windows, с повторными попытками при ошибке. Компьютер
  должен быть включён, пользователь должен войти в Windows, SSH должен быть
  доступен с текущего внешнего IP. Скачиваются новые snapshots, зашифрованные
  отдельным ключом; уже скопированные snapshots пропускаются.
- Независимый репозиторий: `D:\ffmpeg-gui\songs-project-backups\selectel\repository`.
  Политика: 14 дневных, 8 недельных, 6 месячных копий. Журнал `last-run.log`,
  время последнего успеха `last-success.txt` в родительской папке.
- Пароли шифрования и параметры клиента находятся в игнорируемой папке
  `secrets/selectel-2026-10-20`, отдельно от репозитория. При утрате этих паролей
  зашифрованные копии восстановить невозможно. Сохранить их дополнительно на
  личном независимом носителе перед отказом от старых источников.
- Проверочное восстановление независимой копии выполнено в
  `D:\ffmpeg-gui\songs-project-backups\selectel\restore-check-2026-10-20`:
  SQLite integrity_check = ok, все 233 SHA-256 и размеры совпали.
- `songs-monitor.timer` ежечасно проверяет HTTPS, срок сертификата (> суток),
  возраст серверной копии (< 48 часов) и занятость диска (< 80%). Результат —
  systemd/journal, внешние уведомления не подключены.
- Обновления безопасности Ubuntu включены. Node.js, Certbot и restic на ПК
  установлены отдельно и требуют периодического обновления с проверкой работы.
- При смене внешнего IP владельца обновить SSH-правило `/32` в Selectel.
  Никогда не открывать порт 3000 публично. Следить за ростом сохранённых версий:
  они занимают место сверх видимых материалов библиотеки.

Полезные команды на сервере:

```sh
systemctl status songs nginx songs-backup.timer songs-cert-renew.timer songs-monitor.timer
journalctl -u songs -u songs-backup -u songs-cert-renew -u songs-monitor --since today
systemctl start songs-backup.service
/opt/certbot/bin/certbot renew --dry-run --run-deploy-hooks
node /opt/songs/migration/verify-data.mjs /var/lib/songs/songs.sqlite /var/lib/songs/blobs
```

Для восстановления сначала распаковать restic snapshot в **новую отдельную
папку** и проверить базу/хеши через `verify-data.mjs`. В снимке база лежит в
`var/backups/songs-snapshot/songs.sqlite`, blobs — в `var/lib/songs/blobs`.
Только после проверки остановить службу `songs`, сохранить текущие данные для
отката, разместить проверенную базу и blobs в `/var/lib/songs`, вернуть владельца
`songs:songs` и права 700 на каталог, восстановить `/etc/songs/app.env` с правами
600. Не подменять живую SQLite отдельно от WAL при запущенном приложении.
На новом сервере заново установить Node.js/nginx/Certbot/restic и выпустить TLS
сертификат для его адреса; сертификаты и ключ ACME в restic snapshot не входят.
Первый запуск восстановления — с `READ_ONLY=true`, затем проверка всех доступов.

## Первоначальный выбор тарифа (история)

Рекомендация на 19 октября 2026 года: новый продукт VPS/VDS в `my.selectel.ru`,
VDS 2-2-40: 2 vCPU, 2 ГБ RAM, локальный диск 40 ГБ, 400 рублей в месяц по
[публичной странице](https://selectel.ru/services/cloud/vps-vds/).
Российская локация, Ubuntu 24.04 LTS, SSH по подготовленному публичному ключу.
Окончательную цену и доступность проверить в панели до заказа. Бюджет проекта
до 2 000 рублей в месяц; стартовый резерв на инфраструктуру 700–1 000 рублей
с учётом домена и внешнего резервирования. Суммы кроме сервера — плановые лимиты,
а не котировки услуг.

Сейчас материалы занимают около 1,33 ГБ; проектировать хранение под 15 ГБ.
На старте достаточно одного сервера с Node.js, SQLite и HTTPS-прокси. Платные
управляемые базы, Kubernetes, CDN и отдельное рабочее S3 пока не нужны.
Память проверить нагрузочным пилотом. При росте файлов или нагрузки рассмотреть
VDS 2-4-50 за 650 рублей в месяц или отдельное файловое хранилище.

VDS использует локальный диск. Автоматические бэкапы сетевых дисков к нему
не применимы: нужны согласованные копии SQLite и файлов на независимый носитель.
Для облачного резерва рассмотреть приватное S3 в РФ с ограничением бюджета,
проверкой восстановления и шифрованием. Три экземпляра данных провайдера внутри
S3 не заменяют историю версий и независимый резерв. Исходный Яндекс не удалять.

## Первоначальные инструкции владельцу (история, вместо VDS выбран Shared)

1. В существующем аккаунте создать отдельный проект для Songs, включить 2FA.
2. Выбрать VDS 2-2-40 в российской локации, Ubuntu 24.04 LTS. Проверить итог заказа.
3. При создании добавить `secrets/selectel_songs_ed25519.pub` с этого устройства.
   Приватный ключ остаётся только локально в игнорируемой папке `secrets`.
4. Сообщить публичный IP и имя пользователя SSH из панели. Приватный ключ,
   пароль аккаунта, OTP и платёжные данные в чат не отправлять.
5. Для HTTPS API выбрать домен/поддомен. Если домен уже есть — дать возможность
   добавить DNS-запись для API. Если нет — выбрать свободное имя; перед покупкой
   проверить стоимость регистрации и продления.

Для установки приложения на уже созданный сервер достаточно SSH. Полный доступ
к аккаунту и биллингу не нужен. Дополнительные сервисные роли/API-ключи выдавать
только при необходимости автоматизации конкретного сервиса.

## Совместимость ссылок

Старый адрес `github.io/songs/` оставить рабочим. В нём продолжает работать
совместимый фронтенд, который после проверки переключается на HTTPS API Selectel.
Перенос фронтенда только на новый домен не сохранит прежние ссылки сам по себе.
Позже можно добавить переход на новый адрес с сохранением hash-фрагмента.

В базе сохранить исходные ID папок и существующие ключи всех 11 пространств,
ключ преподавателя и ключи песен. Это сохраняет как ссылки учеников, так и
преподавательские глубокие ссылки и адреса отдельных песен.
Приватная таблица ключей не должна попадать в Git, статический сайт или открытое
файловое хранилище. Для интерфейса копирования ссылок понадобится защищённое
хранение исходных ключей; один хеш без исходного значения для этого недостаточен.

- [ ] Проверить прежние ссылки в браузере; сохранить возможность отката с учётом

Старый Google-резерв содержит 9 пространств и не должен незаметно заменять новую
полную библиотеку при сбое. Перед переключением явно решить его судьбу: обновить
до согласованного снимка или отключить такой fallback для нового API.

Рабочее переключение выполнено; текущее состояние описано в начале документа.
При аварии после появления новых правок не переключать запись обратно в старый
Яндекс без переноса дельты из Selectel: это создаст два расходящихся источника.
Для безопасного отката сначала закрыть запись, сохранить актуальную базу и
blobs, восстановить работоспособность Selectel либо согласовать обратный перенос.
Версии старой функции сохранены приватно в `secrets/selectel-cutover`.
