# Сад звука — мобильное приложение

Первая тестовая версия Flutter для Android и iPhone/iPad. Сайт работает параллельно;
API, материалы и права общие, на Selectel. Windows-цели нет.

## Обновление 0.4.0+6

https://135.106.183.211/downloads/sad-zvuka-0.4.0-test.apk

Установка поверх 0.3.0 без удаления, подпись сохранена. Android PCM-метроном
работает отдельным foreground service: панель можно закрыть, приложение свернуть,
останавливать через панель/уведомление. Нужны обычные уведомления Android, разрешение
запрашивается при первом запуске. 1–12 долей с выключением отдельных долей;
преподаватель выбирает из 12 ритмов, ученик — обычные щелчки. Не синхронизируется
автоматически с битовой сеткой песни. Скорость песни 0.50–1.50×, шаг 0.01.
Навигация сохраняет текущую запись, отзыв доступа и выход останавливают её.

«Изменить» открывает настоящий rich-text редактор с цветами букв/маркера HEX/RGB.
Учителю также доступны название, перевод, заметки; в кабинете — изменение имени
пространства и добавление песен, меню дорожки позволяет заменить аудиофайл.
Учитель скачивает из меню дорожки, ученик — кнопкой скачивания. Уже сохранённый
файл остаётся на устройстве независимо от последующего архива.

«Таймкоды» — выбрать минус, заполнить мм:сс у строк или «Сейчас», сохранить;
после нажатия на строку/время запускается привязанная минусовка. При замене TXT
или аудио требуется новая привязка. Восемь вариантов шрифта текста.

98 Flutter-тестов, 101 Node-тест, 6 Kotlin-тестов и analyze/сборка проверены.
Физический Pixel: проверить фон с заблокированным экраном, песню+метроном,
кнопку остановки в уведомлении, системное сохранение/выбор файла. Измеренной
точности на устройстве пока нет. Нативный метроном реализован только для Android;
iOS-сборка и Apple-интеграции не запускались.

## Команды на этом компьютере

Из каталога `mobile` в PowerShell:

```powershell
$env:GRADLE_USER_HOME = 'D:/devtools/gradle-cache'
& D:/devtools/flutter/bin/flutter.bat pub get
& D:/devtools/flutter/bin/flutter.bat analyze
& D:/devtools/flutter/bin/flutter.bat test --timeout 60s
& D:/devtools/flutter/bin/flutter.bat build apk --debug
```

APK: `build/app/outputs/flutter-apk/app-debug.apk`. Это сборка с отладочной
подписью для тестовой установки, не пакет для публикации в магазине.
Обновления из магазина и постоянный ключ подписи ещё предстоит настроить.
На новом компьютере использовать собственные пути SDK и выполнить `flutter doctor`.

Безопасная проверка API (только чтение) на компьютере владельца:

```powershell
& D:/devtools/flutter/bin/dart.bat run tool/verify_selectel.dart
```

Она читает существующий закрытый `../secrets/teacher.env` и частный baseline
переноса; не передавайте эти файлы разработчикам/ученикам. Проверяет учительскую
и изолированную ученическую библиотеку, TXT и Range 0–1023 аудио. В отчёте
`../outputs/mobile-selectel-verification.json` только числа, без имён и ключей.

## Следующая обязательная проверка на устройстве

На Android установить тестовый APK и вставить личную ссылку. Проверить:

1. Список, поиск, открытие песни, TXT/перевод/заметки, вход после перезапуска.
2. Play/pause, seek на паузе и при игре, продолжение после seek, смену варианта.
3. Скорость, повтор, проводную/Bluetooth-гарнитуру, уход в фон и блокировку экрана.
4. Потерю/возврат сети, истёкшую ссылку медиа и повторную загрузку.
5. На временном ученике — архив/восстановление с сайта, отказ в приложении и
   возврат по тому же ключу. Настоящих учеников ради теста не архивировать.
6. Выход во время загрузки, повторный запуск без сохранённого входа.

Физического телефона/эмулятора в текущей сессии не было. Само воспроизведение,
фоновый сервис и поддержка кодеков на Android/iOS ещё не подтверждены устройством.
iOS не собиралась; необходим согласованный Mac, signing и TestFlight. Не выдавать
успешный APK-build и widget-тесты за проверку звука на телефоне.
